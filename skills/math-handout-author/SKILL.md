# 数学讲义制作

## 先确定事实源，不套用历史模板

1. 从用户指定文件或当前教学库确定本次产品、对象、来源、制作范围及交付位置。读根 `AGENTS.md`、`_system/规范/README.md`、总规范，以及索引指向的产品规范、模板说明和实际正文。路径按当前根解析，不写死个人目录；找不到时声明缺口，不能拿工作台代码文档代替教学资料库。
2. 先区分新编、改编、定向修订、装配。既有稿保留稳定 ID、来源、完整小问、图资源和 `needs_review`；用户允许制作一份讲义不等于允许批量迁移属性或改全库。若只要求方案，交付方案而不写正式正文。
3. 本次直接要求与适用规范冲突时，指出具体冲突再定方案。历史模板的结构、属性和题量不自动构成当前全库契约。入口见 [本地规范导航](references/local-contracts.md)；该文件是导航与核查提示，不替代实时规范。

## 编写流程

- 明确本讲目标、必要先修、产品应收范围与本次课堂选用。已有资料优先；缺题可以自编并明确性质，不能虚构教材出处、年份或母题关系。只有关键缺口阻碍正确交付时问用户。
- 根据课型组织内容：同步、复习、专题、试听、模型和大学阅读有不同结构。完整收录与本次必做/课后/选学分开；整讲层级不自动分配给每道题。题量和用时包含学生思考、书写、反馈及缓冲，预算不冒充试教结果。
- 知识陈述写清对象、条件、含义和必要依据；证明不必强塞 Callout。原题中的完整证明、作图与混合小问不得为判断/填空格式硬拆。确需新题组时按产品规定组织真实变化，不机械复制或凑配额。
- 每道题先完整呈现题干和小问，再就地放标准答案、补充解析、评价要点。必要证明和计算步骤属于标准答案；不移到仅教师解析中，不复制一份集中答案。共享条件拆成单题时随题带齐。
- 独立检测使用未展示且符合目标的任务，题头、前文与图不得提前泄露待考方法。题目是否已经见过无法确认时，标“独立性待核”，不要宣布已形成独立掌握证据。
- 数学正文分数按现行规范使用 `\frac{分子}{分母}`；不把路径、日期、单位约定或非数学斜线机械替换为分数；图示与实际条件、方向、端点和数值对应。题目逐一独立求解，核对可行性、分类、取等点与必要图示；来源不清与数学不确定分别记录。

## 属性和输出适配

按当前属性规范保留字段类型、唯一标题和正文归属；不以补齐属性提升审核状态，不删除历史有效字段。仅涉及对应范围时读取 [Mathsemble 与验证边界](references/output-validation.md)。

Markdown 是当前 Markdown 产品唯一可维护母稿；学生/教师版本由显示策略派生，不维护两份可各自修改的题文。原生 TeX 出版产品仍按其独立契约，不为本技能统一强转。

## 交付与停止条件

交付前复读整份草稿（含公式、答案、解析及规范未知时的回退草案），逐处核对数学除法的分式写法：例如 `e=c/a`、`e=4/5` 应写为 `$e=\frac{c}{a}$`、`$e=\frac{4}{5}$`。只改数学含义明确的分数，保留原数值、括号与定义域；路径、URL、日期、单位约定和用于展示原样语法的行内／围栏代码不做全局斜线替换。

交付讲义或指定范围的修订，以及简短的：本次范围/依据、内容与题目覆盖、课堂选用、尚缺内容、验证结果。来源证据放在产品要求的位置，学生页不堆重复来源标记，但不得据此删除必要追溯数据。

分别报告结构与属性、数学、来源、答案显隐、图形实际渲染、真实 Obsidian、PDF/打印和课堂使用的 `PASSED / FAILED / NOT_RUN`，限定检查范围。已检查但证据不足、无法裁决的具体事项另列“待核/needs_review”，说明缺什么证据；不误记为已通过、已证伪或未检查。未做的层不算通过。决定题意的条件缺失、关键答案未解决或学生版可能泄漏时，先修正或明确排除相应任务；保留其余已验证成果，不隐瞒缺口，也不无限扩张项目。

正式文件写入前重新读目标以发现并发改动；有冲突停下比对。新候选留独立位置，不覆盖原稿或部署插件，除非本次授权包含该动作。
