# 课堂反馈与独立验证工作框架

家长稿由教师审定。使用工作台时，按本项目的字段和权限保存实录。

## 一、课后随手发文字

直接提供自然语言即可，不必填完整表格。最好带学生姓名、实际课日或明确周范围、做了什么、能否独立完成和下次想检查什么。缺项不妨碍保存已经明确的部分；身份或时期无法唯一对应时，先问最小必要问题，不猜配学生或课次。

需要时复制这份简表；这是空白输入模板，不是课堂事实：

```text
学生：
实际课日／周范围（不清楚可直接说）：
本课内容与表现：做了什么；独立做到哪一步；给了什么提示，之后怎样。
作业／复测回收：实际看到什么；学生或家长自述另标；没检查就写没检查。
典型卡点与补救：卡在哪一步；当堂采取什么处理；结果怎样。
下次安排：已有安排；希望下次验证的问题。未定日期可写“下次实际课”。
```

原始文字的来源、事件时间与录入时间分开。只知道周范围时保留周汇总和空课日；单课日期不明不能为了回流补成整理当天。多人同课分别记录个人表现，共同内容不能推出相同掌握程度。

## 二、先记观察，再判断独立程度

在原有实录字段里写清下列信息，不增设等级列，也不把这些称呼批量贴到旧记录上：

| 证据情形 | 实录怎样写 | 当前可作的判断 |
| --- | --- | --- |
| 听讲后表示理解／学生自述会做 | 注明是谁说的、何时说的，是否看过过程 | 独立完成未验证 |
| 提示后完成 | 记录提示发生在哪一步、具体提示和后续结果 | 仅确认在该支持条件下完成 |
| 无提示独立完成 | 记录任务、过程、正确情况；有题数或用时才填写 | 该任务范围内独立完成，隔课保持与迁移另查 |
| 当堂订正或重做原题 | 记录订正内容及是否仍需提示 | 当堂改正，不当作隔课复测 |
| 隔课换题独立完成 | 记录实际日期、任务变化、支持条件与结果 | 形成保持／迁移证据，结论限于验证范围 |
| 没测、没收回或材料不全 | 如实写未复测、未回收、未见过程 | 保留未验证，不判成不会或未完成 |

“理解不牢”“审题问题”等原因判断与观察分开；有线索但未验证时写“待验证”，随后安排能区分原因的任务。忘带作业不等于没做；做完不等于做对；讲过和课程完成不等于稳定掌握。

## 三、落到现有工作台与档案

| 本次整理内容 | 现有保存位置 | 档案或后续用途 |
| --- | --- | --- |
| 真实任务和实际讲授 | 课堂记录的“实际内容” `actual_content` | 回流“本课内容与表现” |
| 过程、提示、观察依据及判断边界 | “教师备注” `teacher_notes`；有明确目标时填目标评价依据 | 回流保留依据，避免只留下“掌握较好” |
| 作业提交、订正、隔课复测 | “作业情况” `class_performance.homework` | 回流“作业／复测回收” |
| 具体卡点、实际补救及结果 | “错题与易错点” `class_performance.mistakes` | 回流“典型卡点与补救” |
| 明确的下次安排、作业与实际沟通 | `next_plan` | 回流“下次安排及沟通”；拟议与已确认分开写 |
| 下次要独立完成的任务、检验方法 | 下一课的个人目标 `prep_member_goal`、当堂检验 `prep_check` | 写入已有未授课计划；没有计划时才建空日期草稿 |

目标评价 `objective_status` 沿用空白（未评价）／达成／部分达成／未达成；“未验证”写在依据中，不发明新的枚举。没有当时的目标或评价证据，就不从当前新拟目标反填历史达成情况。下一课计划也不写入历史实录的计划栏。

处理顺序：

1. 重新读取对应学生档案、准确课次和当前源文件，核对同源记录；按 `session_id` 更新，避免收到补充文字便新增重复课次。
2. 将真实课堂内容保存为实录，再读回核对。修订既有事实保留原因与原值；更正身份、日期、周次按现有订正流程处理。
3. 用现有回流流程核对目标档案及四项内容，更新同一课次的受控片段。保留人工历史、当前画像与评分，不另手抄同一课次，也不直接改受控标记。
4. 需要调整当前重点时，引用本次证据，在既有最多三项重点中维护下一步及验收标准；不新增第二张待验证清单。框架搭建本身不调整学生画像和六维分数。
5. 有可验证的下一步时写入下一课目标与当堂检验。日期未定保持草稿。只有明确需要跨周追踪的事项，才用工作台已有“持续跟进”，不从所有备注自动制造任务。

实录、档案回流和下一课计划分别核验：一处成功不代表全部完成。回流失败时保留已经保存的实录，从原课次重试，不再次造课。工作台有未保存输入或源文件变化时先保留输入、刷新核对，不能用旧面板覆盖新数据。

## 四、下一课怎样验证

把这张卡的内容放入下一课“当堂检验”，不另建结果库：

```text
要验证的问题：〔一个具体卡点，引用上次日期／session_id〕
任务与材料：〔换题、条件或表达的变化；具体材料未选就注明待选〕
独立条件：〔先无提示作答；需要帮助时记录首次卡住的位置和实际提示〕
观察点：〔关键一步、理由、步骤或检查行为〕
验收标准：〔本次计划判断什么，题量／用时阈值按目标拟定〕
验证时间：〔下次实际课；只有已确认排课才填日期〕
```

验证后，结果写在**新课次**的作业／复测回收与目标评价依据中，并引用原卡点来源。记录“独立做到哪步、提示后怎样、是否需要再次验证”。当堂再练和隔课换题分别判断。尚未实施时保留未复核及原因，不因到期直接判未达成。

如需持续跟进，完成事项时仍记录实际结果；“检查已完成”不等于“学生已掌握”。当前重点的计划、未复核、达成、部分达成、未达成、证据不足沿用档案规范，按真实结果更新。

## 五、交付与家长审定

每次完成后简短回执：

- 已更新哪些学生、哪些课次／周范围；实录、档案和下一课计划各自是否保存成功。
- 本次独立表现的证据边界，以及下一课具体检验什么。
- 必须确认的缺项或冲突；能确定的内容先交付。
- 如起草家长版，明确“待教师审定，未发送”。

家长版沿用上课内容、课堂表现、知识点掌握、规划建议、课后作业五段。教师内部判断不原样复制给家长；提示后完成如实表述，规划以教师后续安排为主。已布置的作业与建议练习分开，不从旧周默认本周布置或完成。草稿、复核、复制和实际发送分别记录；原发送历史不因修改正文而消失。
